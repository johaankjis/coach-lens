# AWS-2: Real ResultsCX evidence boundary

AWS-2 permits a narrowly prepared, **structured-only** ResultsCX diagnostic bundle to reach Bedrock from the explicit local three-workbook demo loader when `COACHLENS_BEDROCK_ENABLED=true`. Evaluator comments stay local by default; see [Default: structured evidence only](#default-structured-evidence-only). It does not authorize arbitrary normalized JSONL, API-submitted records, or a caller's safety assertion. The default constructor and normal API startup remain privacy blocked. The synthetic AWS-1 smoke path remains separate.

## Local and remote evidence

The M2 `Evaluation` and `CriterionResult` records, original comments, source QA scoring, local IDs, and `SourceLineage` stay local. M3 produces deterministic signals and an `EvidenceBundle` with exact source rows. AWS-2 applies a local text policy, projects only explicitly allowlisted facts, and assigns fresh `SIGNAL-001` and `EVID-###` references. The local preparation object retains `EVID-### -> local evidence ID -> evaluation ID -> SourceLineage`; only the opaque reference crosses the provider boundary. The normal M3 citation validator then checks the mapped local citations against the exact bundle stored for human review.

The wire object has exactly `signal`, `evidence_items`, and `text_coverage`.

`signal` permits `reference`, `domain`, `criterion`, `failed_criterion_result_count`, `passed_criterion_result_count`, `evaluated_criterion_result_count`, `failure_rate`, `pass_rate`, `evaluations_containing_criterion`, `total_loaded_evaluations`, `feedback_count`, `feedback_coverage`, `max_score_total`, `attained_score_total`, and `score_rate`.

Each `evidence_items` entry permits `reference`, `domain`, `criterion`, `failed`, `max_score`, and `attained_score`. The wire schema also reserves `diagnostic_text: {kind: "minimized_evaluator_feedback", text: string}` for a future `ALLOW_MINIMIZED` decision, but **in the current milestone the real path never emits it** (see below); the reasoner refuses to invoke if it appears. The original answer string is excluded; `failed` comes from M2's pass marker. Criterion wording is used only when it passes the narrow text policy unchanged; otherwise it becomes `[criterion withheld]` in the remote projection.

`text_coverage` permits `total_evidence_items`, `evidence_items_with_feedback`, `minimized_text_items_allowed`, `text_items_blocked`, and `text_items_with_no_text`. Counts are deterministic per signal. `evidence_items_with_feedback` is M2's nonempty-string count; a whitespace-only value can count there while receiving `NO_TEXT` under AWS-2. On the wire, `text_items_blocked` means "local text existed and was not transmitted", whether the minimizer refused it (`BLOCK`) or the milestone default withheld it (`WITHHELD`); `minimized_text_items_allowed` is therefore `0` on every real request today. A withheld or blocked row still contributes its structured score facts. The model prompt states that feedback may have been withheld, forbids inventing it, and asks for lower confidence or `undetermined` when qualitative evidence is insufficient.

No remote field intentionally serializes agent, QA evaluator, or team-leader names; raw evaluator comments; raw answer strings; local evidence or evaluation IDs; `SourceLineage`; workbook filename, sheet, path, or row; or a raw M2/M3 model. The Bedrock request is built by naming each field, never by dumping a raw domain object. Tests assert the exact key sets and inspect a mocked Converse request.

## Default: structured evidence only

**Real evaluator comments are not transmitted in this milestone.** This is a deliberate safety decision, not a technical limitation. The deterministic minimization machinery below is implemented, tested, and exercised locally on every real request so that coverage accounting is exact, but its `ALLOW_MINIMIZED` outcome is recorded locally as `WITHHELD` and no `diagnostic_text` is placed on the wire. Bedrock receives deterministic counts, rates, coverage, score facts, opaque references, and policy-approved criterion wording only. Raw comments remain available unchanged to the local reviewer and evidence-inspector routes.

Activation is a separate reviewed **code** change (passing `transmit_minimized_text=True` from the reasoner) that requires a local-only evaluation of the policy against the actual ResultsCX dataset first. There is deliberately no setting, environment variable, request field, header, or query parameter for it; `COACHLENS_ALLOW_REAL_TEXT`, `send_comments=true`, `safe=true`, and similar are ignored, and tests assert this. Known residual gaps that motivate the deferral: sentence-initial unknown names, lowercase-written unknown names, nicknames, health-related text without an explicit identifier, and identifying combinations of ordinary words. No claim of anonymization, PHI-free text, or HIPAA compliance is made.

## Local free-text decisions (implemented; remote activation deferred)

`NO_TEXT` applies to missing or whitespace-only comments. `WITHHELD` applies to text the minimizer would admit while remote real text is disabled (the current default). `ALLOW_MINIMIZED` is a narrow permitted-content decision, not the absence of detected risk. After NFKC normalization and trimming, text crosses only when **all** of the following hold:

1. It is at most 1,000 characters and every character is a Latin-script letter, a space, or one of `. , ; : ! ? ' " ( ) -` and the curly quote / dash equivalents. Digits, `@`, slashes, brackets, underscores, other symbols, control and format characters (including zero-width characters), non-Latin letters, and emoji all block. A period followed directly by a letter (a domain or filename) blocks.
2. Every recorded agent, evaluator, and leader name in the loaded population is replaced by `[redacted]`, both as the whole name and as each letter-run part of at least two letters (so `Alice`, `Canaryson`, `Alice-Canaryson`, and `ALICE CANARYSON'S` are all suppressed for a recorded `Alice Canaryson`). Any residual whole name, or any residual five-letter-or-longer name part embedded in another word, blocks.
3. No honorific token (`mr`, `mrs`, `ms`, `mx`, `dr`, any case) remains.
4. No capitalized word remains that is not sentence-initial, a single letter, or one of a fixed QA-role vocabulary (`Agent`, `Member`, `Caller`, `Customer`, `Patient`, `Provider`, `Rep`, `CSR`, `QA`, `TL`, `DOB`, `ID`, `SSN`, `MRN`, `PHI`, `PII`, `HIPAA`, `EOB`, `PCP`, `IVR`, `OK`, `I`). Mid-sentence capitalized words are treated as possible proper nouns (members, relatives, clinicians, facilities, places, months, brands), and all-caps comments block for the same reason.
5. Substantive words remain after suppression.

Everything else is `BLOCK`: local text existed but was not transmitted. The same rule decides criterion wording; a Title-Case or numbered question is withheld as `[criterion withheld]`. These decisions run locally and deterministically. The policy preserves the remaining wording; it does not infer themes or causes.

This is data minimization, **not anonymization** and not PHI detection. It does not detect a sentence-initial unknown name, a name written in lowercase, a nickname, a health condition or treatment named without an identifier, or an identifying combination of otherwise ordinary words. A permitted comment is not certified PHI-free. CoachLens does not claim HIPAA compliance from this mechanism alone. Expect the policy to block many genuine comments (emphasis in capitals, ticket numbers, dates); that is the intended direction of failure. Review the policy, source criteria, access controls, and deployment before any production use. The local reviewer evidence routes still expose raw evidence and need their own access controls.

## Enablement and review

Only `load_results_cx_demo` can mint the in-process trusted container after the exact three required workbooks pass M2 discovery and normalization. The container holds its own deep copies, is immutable, refuses copy and pickle reconstruction, and records a content digest at mint time; a subclass or a value-equal plain list is never accepted. `install_results_cx_demo` installs the real-capable reasoner only for that exact type and only when Bedrock is configured. The reasoner verifies the digest, binds to a private deep copy of the population, re-verifies the digest before every invocation, reconstructs and checks the M3 provider view against its private records, prepares the real wire bundle itself, and validates its allowlist before calling Converse. Changing a record after loading, even with the same identifiers, therefore blocks invocation rather than changing what is sent. A plain list, the normal JSONL startup, an environment variable claiming safety, or an HTTP body/header/query assertion cannot unlock it. This is an in-process authorization boundary against public callers, not a defense against arbitrary code execution inside the server.

Bedrock output retains AWS-1's exact JSON schema, stop-reason and citation checks, sanitized errors, no repair or fallback, and service-stamped `generation_mode`. A successful diagnosis enters `awaiting_review`; a supervisor must Approve, Reject, or Revise. Failure frequency alone does not establish a training need, and `undetermined` remains a valid diagnosis.

The default model ID remains `global.anthropic.claude-sonnet-4-6` and the client region remains `us-east-1`. **The global inference profile may route processing outside the client region.** `invocation_region=us-east-1` records the client endpoint setting, not a guarantee of in-region processing.
